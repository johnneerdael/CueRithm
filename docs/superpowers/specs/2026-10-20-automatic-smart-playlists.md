# Automatic Smart Playlists

User authorization: design and implement in a new worktree through reviewed PR merge without approval checkpoints.

Add Settings → Smart Playlists with independent Artist, BPM, Release date, Genre and Key switches, disabled by default. Keep time zone and key preferences on Library preferences. Save automatic settings with the same revision-checked preference API. BPM supports zero to ten configured inclusive finite ranges, positive and at most 999 BPM; reject reversed ranges and duplicate ranges. Overlaps are allowed and tracks may belong to both. Inactive BPM ranges never block disabling the option or saving unrelated preferences; omit incomplete or invalid range drafts from the UI save payload when BPM is off.

Use managed ordinary smart-list definitions under Automatic Smart Playlists / Artists, BPM, Release dates and Genres. Release dates contain year / month folders and four smartlists named Month, Year; Warm-Up Month, Year (energy 1–5); Dancefloor Month, Year (6–7); Anthems Month, Year (8–10). All month lists include every prepared non-archived track with that release month, including tracks without energy. Do not invent a month for year-only dates. Recognize explicit release tags, including Beatport RELEASE_TIME, before DATE. Accept valid YYYY-MM and YYYY-MM-DD dates; reject malformed dates and timestamps.

Read artist and remixer credits separately, split comma, semicolon and explicit collaboration markers, deduplicate case-insensitively, and match complete individuals rather than substrings. Use named remix credits from titles when no remixer tag exists. Preserve multi-value genre metadata and match individual genres. Use effective metadata after cleanup. Generated nodes have stable managed identities independent of user names. Manual nodes are never adopted by matching names. Enabled categories maintain generated smartlist rules while preserving user names and folder positions. Duplicate a list to customize its rules. Disabling an option stops creating nodes and preserves existing lists. Removing BPM ranges preserves their existing lists; active range definitions are identified by bounds. This avoids deleting user organization. Generated smartlists retain live membership when creation is disabled.

Reconcile on settings save, explicit refresh, application startup and smart-service input revision changes, so incoming completion and metadata edits expand new artists, genres and dates without opening Settings. Reconciliation and preference saves are atomic, revision checked, and idempotent. Generated updates do not replace the user's undo entry. Preserve all music and tags; this feature changes library data only.

Read-only metadata audit: 434 FLAC files; all have full DATE and RELEASE_TIME dates and YEAR. 427 DATE values agree with RELEASE_TIME; prefer explicit release time. 233 contain collaboration markers; 45 have REMIXER. Identifying audit stays in ignored .analysis; publish aggregates only.

Verification: backend tests for boundaries, date priority/precision, contributors and remixer fallback, lifecycle expansion/restart/idempotence, manual isolation, compatibility and invalid settings; UI tests for independent switches, ten-range cap, validation, save/reload errors; screenshot of settings; workspace tests, formatting, clippy, release build and frontend suite/build; review latest PR head and CI before merge. No release/version changes.

Key addition: opt-in creates all 24 Camelot key lists, each using KeySimilar and the library compatibility preference (harmonic by default), with no extra BPM restriction. Static inspection of Lexicon 1.11.15 confirms KeySimilar delegates to harmonic/fuzzy compatibility; generator ranges and numeric Between use inclusive bounds. Private inspection of 819 existing lists confirms artist-or-remixer rules, monthly energy partitions and 24 key-similarity lists. Existing month lists use comment suffixes; the new feature uses actual release metadata. No proprietary code or private playlist contents are published.
