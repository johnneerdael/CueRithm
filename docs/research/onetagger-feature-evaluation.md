# OneTagger feature evaluation for CueRithm

The recommendation is to extend CueRithm's automatic preparation and library editing, with safe file organization as the largest missing capability. Retain the existing matching/tag-writing adaptations. Add match review, a shared metadata editor and a keyboard-friendly Curate inspector. Evaluate additional providers individually. Do not transplant OneTagger's file-mutation runtime or duplicate its application shell.

See the [requirements](../brainstorms/2026-10-20-onetagger-library-preparation-requirements.md), [issue audit](onetagger-issue-audit.md), [current alternatives and DJ data](onetagger-alternatives-and-data-sources.md), [implementation plan](../plans/2026-10-20-001-feat-library-preparation-workflows-plan.md) and [visual proposal](../design/onetagger-preparation/index.html).

## Maintenance assessment

The repository is not archived. Its latest default-branch commit is a February 2026 CI rebuild; the preceding substantive provider/platform work is from August 2025. The latest published release is still [1.7.0 from August 2023](https://github.com/Marekkon5/onetagger/releases/tag/1.7.0). The maintainer's [issue notice](https://github.com/Marekkon5/onetagger/issues/363) describes delayed work and known service/rate-limit problems. [Recent discussion](https://github.com/Marekkon5/onetagger/issues/531) reports failing functions and asks about alternatives.

This supports planning for independent maintenance and a long-lived fork boundary. It does not establish a formal abandonment announcement. Release age, source age and current endpoint health are separate facts. Current history is visible in the [commit log](https://github.com/Marekkon5/onetagger/commits/master/).

## What must not be pulled in unchanged

| Finding | Evidence and present reachability | Planning consequence |
|---|---|---|
| Unsafe organization executor | Upstream renamer performs direct copy/rename/delete; sample preview takes only three files; template constants and final joined paths lack a containment boundary. It is not imported into CueRithm. | Reuse ideas/grammar only after validation. Build a frozen full-batch plan and coordinated source-path transaction. |
| Silent destination collisions and misplaced art | `move_file` can return an existing target as success; upstream artwork is written independently of the later move. Reports [#475](https://github.com/Marekkon5/onetagger/issues/475), [#474](https://github.com/Marekkon5/onetagger/issues/474) and [#504](https://github.com/Marekkon5/onetagger/issues/504) matter. | No overwrite or silent skip; include owned sidecars in the final destination transaction and result counts. CueRithm's current sidecar writer is separately adapted. |
| Wrong recording/version confidence | Normalization can remove edition information. [#529](https://github.com/Marekkon5/onetagger/issues/529) cannot be resolved by promising a 95% safe threshold. CueRithm already repairs the upstream fuzzy-duration gap with pre/post filters. | Version constraints, stable IDs, duration evidence, release tie-breaks and ambiguity review. Preserve score as similarity, not probability. |
| File/tag corruption reports | [#121](https://github.com/Marekkon5/onetagger/issues/121) describes historical DJ metadata loss with subsequent claimed fixes; [#315](https://github.com/Marekkon5/onetagger/issues/315) is an unresolved M4A report. Upstream ID3 loading can replace a failed parse with a fresh tag; CueRithm already refuses unreadable source tags and stages writes. | Keep PCM/timeline checks **and** assert opaque Serato/rekordbox/other native metadata preservation. Audio equality alone is insufficient. |
| Policy gaps and misleading success | Upstream explicit-status writing bypasses overwrite policy; CueRithm's corresponding writer retains that gap, currently dormant because its two providers do not supply Explicit. Artwork/lyrics can fail separately from matching. | Fix before adding providers that return those fields. Surface per-field outcomes and preserve protected values. [#327](https://github.com/Marekkon5/onetagger/issues/327) itself is explained by overwrite-all configuration, not proof every title write ignores policy. |
| Quick Tag data loss and shared-frame collisions | Reports [#356](https://github.com/Marekkon5/onetagger/issues/356), [#400](https://github.com/Marekkon5/onetagger/issues/400) and [#501](https://github.com/Marekkon5/onetagger/issues/501) concern dirty drafts and overlapping category/comment mappings. | Durable drafts, explicit mixed/keep/set/clear/append semantics, structured category IDs and collision-aware export mappings. |
| Spotify feature/API incompatibility | Source `Spotify::audio_features` returns `Spotify deprecated AudioFeatures`. Spotify's [2024 access change](https://developer.spotify.com/blog/2024-11-27-changes-to-the-web-api) restricts new use cases; its [2026 migration guide](https://developer.spotify.com/documentation/web-api/tutorials/february-2026-migration-guide) documents removed popularity fields in Development Mode. | Do not offer a nominally working Audio Features mode or treat parser relaxation as restoring endpoint access. Spotify metadata would need a separate access/auth/model audit. |
| Recognition fallback and provider resilience | Shazam is invoked on metadata-load error/force, not reliably on every readable missing-tag file or no-match. Recursive rate-limit retries do not provide a total work budget. CueRithm excludes this runtime. | Explicit triggers, consent/configuration, bundled decode, bounded attempts/deadlines, cancellable waits and distinct unavailable/no-match/review outcomes. |
| Discogs release numbering | Current source indexes an exact release using track number without a complete disc-aware identity contract. | Model disc/track/global position explicitly, reject zero/out-of-range inputs and characterize [#199](https://github.com/Marekkon5/onetagger/issues/199) before provider enablement. |
| Extension/runtime drift | Native plugin download/loading, legacy WebSocket shell, playback regressions and package dependencies recur in issues. | Keep CueRithm's Tauri/bundled runtime. Do not inherit native plugin installation or expose a network server as a shortcut. |

The [complete issue audit](onetagger-issue-audit.md) is the per-ticket record; this table identifies architectural consequences rather than substituting a small sample for the full audit.

### Native editor preflight findings

The PR3 source preflight checked the vendored writer helpers before exposing manual controls. These are source-confirmed helper behaviors, not reproduced user-library corruption reports:

| Helper | Existing behavior | Required editor contract |
|---|---|---|
| ID3 `set_rating` | Overwrite removes every POPM frame and creates one `no@email` entry with a zero counter. | Edit an explicit rating owner; preserve other owners and counters. Do not pass manual rating edits through the existing bulk helper unchanged. |
| ID3 common `set_native("COMM")` | Reads the first empty-description comment, then removes all comments with that description when replacing it. Different empty-description languages can collapse. Named comments are preserved by this path. | Address a comment by language and description, or block an ambiguous common-comment edit until its identity is chosen. |
| ID3 `set_art` | Replaces all pictures of the chosen type. Multiple front covers are not individually identified. | Replace/remove the selected image by type, description and byte digest; preserve other images. Report container differences such as MP4's missing cover-type identity. |
| Review evidence | PR1 stores bounded candidate identity/ranking summaries, but not the complete validated proposed fields/artwork payload. | Retain a bounded selectable payload or explicitly requery and issue a new selection token before acceptance. A summary is not an executable write plan. |

Evidence: `vendor/onetagger/onetagger-tag/src/id3.rs` (`set_rating`, `set_art`, `set_native`), `crates/cuerithm-autotag/src/evidence.rs` and the current metadata/staged-write adapters. PR3 acceptance must independently reread multiple POPM owners/counters, multilingual comments and same-type pictures while also checking PCM/timeline equality. Protected opaque/DJ records remain outside the editable surface.

## Fit with CueRithm

- **Settings:** extend the existing Incoming/Automatic tagging/Cleanup pages; add File organization and later named presets. Keep unnumbered page navigation, draft persistence and Save settings semantics.
- **Incoming:** show actual stage and outcome. Open Review match from attention rows; successful configured work continues automatically.
- **Tracks:** add a selection inspector with Edit and Curate modes, reusing the existing table and bottom player. Selection changes must not unexpectedly change playback.
- **Tools:** add Organize files for existing tracks, using the same executor as Incoming and an all-track before/after preview with guarded Undo.
- **Categories/export:** store mood/vibe/occasion/instruments as structured library data; map to file/native DJ fields only through an explicit supported destination contract. Do not manufacture a second analysis-energy scale.
- **Design:** use current `apps/desktop/src/brand/tokens.css`, fonts and control/panel radii. Historical charcoal/teal specifications predate the shipped cobalt/coral theme.

## Source and service references

- [OneTagger pinned source](https://github.com/Marekkon5/onetagger/tree/36523f71f2d9a5947912f3cb930f1a31fcb2e3ee).

- [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API) requires an identifying User-Agent and at most one request per second; aggregate throttling must span all preparation workers.
- [Rust filesystem rename](https://doc.rust-lang.org/std/fs/fn.rename.html) can replace a destination and does not work across mount points; it is not a complete organization transaction.
- [Windows path naming](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file) informs reserved-name, namespace and path validation, which must be exercised on Windows rather than inferred from macOS fixtures.
