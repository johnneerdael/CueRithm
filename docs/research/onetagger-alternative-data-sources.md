# Current metadata and DJ data alternatives

Checked **2026-10-20** against primary official documentation, terms, publisher sites and the official Songstats repository. No accounts created, credentials used, subscriptions purchased, catalog/recognition API calls made, music uploaded or bulk dumps downloaded. Availability below means a current documented public product surface, not a successful authorized endpoint or measured dance-music match rate. Prices are the published snapshot, not a quote. All recommendations and fit rankings are our planning inferences.

Existing Traxsource code must be retained and its UI remain hidden as explicitly requested. None of the alternatives below requires deleting it, bypassing Cloudflare or evading provider limits.

## Recommended shortlist

1. **MusicBrainz core metadata + Cover Art Archive**: strongest open identity/release foundation; use edition-aware lookup and explicit source/rights provenance. Evaluate genre licensing separately from core identifiers.
2. **Official Beatport partner route**: highest likely dance-version value, but approval, retention and tagging/export rights must be obtained rather than inferred from visible API URLs.
3. **Selected provider update:** implement optional personal-key SonoVault alongside MusicBrainz. Musicfetch is excluded by the user: its seven-day trial is not an ongoing free plan. The inventory retains its researched facts without recommending an adapter.
4. **Music Story versus Soundcharts commercial evaluation**: Music Story is closer to catalog identity/cleaning; Soundcharts offers accessible metadata/audio-descriptor endpoints and batch/feed infrastructure. Neither should enter unattended Incoming until permanent metadata/export rights and exact endpoint entitlements are explicit.
5. **Wikidata as a small curated taxonomy reference**, not a per-track classifier.
6. **Songstats as optional DJ-context enrichment**: specific advantage is documented 1001Tracklists/Beatport/Traxsource ecosystem coverage. Chartmetric/Viberate are mostly analytics and lower priority for local-file tagging.

## What this means for large DJ libraries

**Lookup API capacity is not catalog-ingestion capacity.** At MusicBrainz1 request/second,100k requests alone require at least27.8 hours; real release matching may require multiple calls per file. Musicfetch6/20/40 RPM implies100k requests need roughly11.6/3.5/1.7 days continuously, before retries and shared-account load. Those calculations are arithmetic floors, not service throughput promises. Quota, rate, concurrency, batch size and endpoint cost must be separate recipe estimates. A desktop containing100k files should not automatically download every global catalog dump.

Recommended architecture is a **source-aware enrichment adapter** returning candidates and per-field evidence, with scheduler/budget/cancel/backoff and optional approved cache. Each stored value needs source/entity ID, exact edition/version, retrieval time, confidence evidence, licence/retention policy and whether it may enter tags or native exports. Matching by ISRC narrows candidates but does not prove exact mastering/clean/extended/version equivalence. Catalog year, earliest known release and purchased-edition date remain separate fields.

Keep CueRithm PCM-derived key/BPM/whole-track energy and existing cue DSP authoritative by default. A third-party tempo/key/energy field is a separate source and may refer to a radio edit. Extra descriptors belong to optional enrichment, not a replacement analysis model or a new mandatory Incoming dependency. User-curated tags remain protected values.

**Catalog metadata, semantic descriptors and DJ context are three different contracts.** MusicBrainz/MusicStory/Discogs primarily help identity and releases; Soundcharts offers documented descriptor fields; Songstats offers the clearest investigated DJ-platform context route. Artist popularity/followers do not establish track suitability, exact mix identity or set function.

## Concrete evidence gates before selecting a paid alternative

- Confirm own desktop application use is authorized; distinguish user-owned API key from shared application backend/account plans.
- Obtain written field/source entitlements and permanent audio-tag/native DJ export/offline-retention rights. A promise of API access, SDK MIT licence or artworkURL is insufficient evidence.
- Run a separately authorized bounded trial across representative electronic subgenres, old vinyl/CD, mainstream, bootlegs/unreleased material and clean/dirty/radio/extended/remix variants. Keep source originals untouched and label unsupported coverage honestly.
- Compare accepted exact-edition matches, ambiguous matches, false positives, missing fields, original-date semantics, artwork correctness and per-track total cost/request count. Avoid a single match-rate metric that rewards unsafe substitutions.
- Exercise cancellation,429/Retry-After, challenge/HTML responses, deprecation/schema changes, cache expiration and quota exhaustion. Provider failure should pause enrichment or enter review while preserving completed local analysis.
- Preserve Traxsource implementation and hidden UI status. Any future restored exposure needs its own source-health/permission evidence; aggregation vendor coverage does not automatically authorize direct scraping.

## Sonovault additional evaluation — checked 2026-10-20

**Approved selection:** add optional personal-key Sonovault; exclude Musicfetch. The user approved proceeding on the optional personal-account interpretation after reviewing section 9. Only users choosing SonoVault need a key; CueRithm itself does not require one. Its founder describes DJ-library origins and a reconciled catalog, making it more directly relevant than artist-analytics platforms. Claimed 93M+ size, latency, uptime and coverage remain vendor statements, not measured acceptance. Its underlying open sources overlap MusicBrainz/Discogs, so compare the value of its reconciliation and operation against using those directly. [About](https://sonovault.now/about).

**Source provenance.** Sonovault describes MusicBrainz dumps/live feed, Discogs monthly dumps, Wikidata artist enrichment and MLC recording/work links. It also reports cross-checking storefront/platform catalog fields, specifically electronic genres from Beatport. Those statements explain its potential DJ relevance; they do not transfer upstream access rights to CueRithm or prove per-track provenance accuracy. [Data sources](https://sonovault.now/data-sources).

**Edition and taxonomy constraints.** The API documents mix suffixes in title, but its track has one representative release selected by release type/title/earliest date, plus one representative ISRC. Artist/title search has no separately documented explicit edition constraint. Canonical genre/subgenre arrays can be empty; rare subgenres may fall outside its genre list. The current API documents cursor pagination for search and paginated lists; query depth is bounded. Pin endpoint schemas in acceptance fixtures rather than assuming an exhaustive catalog response. Therefore preserve duration/version/release evidence and do not assume a canonical match identifies the user's pressing, mix or fine-grained style. [API reference](https://sonovault.now/docs). The metadata guide explicitly excludes mood, danceability, energy, popularity, charts, audio previews, artwork and lyrics. It cannot replace Spotify Audio Features or the artwork pipeline. [Scope/limitations](https://sonovault.now/music-metadata-api).

**Permanent tags versus app data are distinct.** Terms§7 expressly permits title/artist/release title/label/genre/date/duration/ISRC in lawfully held end-user audio files, surviving termination. BPM/key/platform IDs are excluded from that list. Paid internal/app-only retention ends with subscription, with 30 day purge; free cache requires 30 day refresh. Native DJ database export is not established. §9 restricts account/key use and quota multiplication. The optional personal-account product decision is recorded above; do not pool keys. Keep retention/native-export capability checks distinct from that credential decision. [Terms](https://sonovault.now/terms).

**Free tier and billing.** Current API docs list 1,000 free requests/month with a 20/minute burst limit, including search, ISRC lookup and platform links; paid recognition/browse are separate entitlements. Dashboard handles 1000 lines through batches of 100; API bulk results retain input order and distinguish matched/notfound/quota-skipped. A batch is not a one-credit 100-track lookup: every processed line costs one. Custom data delivery to S3/GCS/Databricks is offered by agreement, not included full-catalog redistribution. As observed, beta prices €14.50/49.50/124.50/month correspond to standard €29/99/249; promotions need rechecking before budgeting. Current pricing advertises credit top-ups and no automatic overage. [Bulk tool](https://sonovault.now/bulk-lookup), [pricing](https://sonovault.now/pricing).

**Recognition.** Paid endpoint accepts raw audio up to 100 MB, not client fingerprints; cost 10+ started MB credits and a further metadata lookup after matching. Vendor recommends generous audio rather than a fixed short excerpt, returns ranked confidence and states uploads are discarded during the request. This is a potential Shazam alternative requiring explicit upload consent, actual edition testing and cancellation/cost limits. Recognition success is not a licence or exact-version guarantee. [Recognition](https://sonovault.now/identify).

**Fit relative to alternatives.** Musicfetch emphasizes broad links and platform/art metadata; Sonovault offers a narrower text-catalog/identity service and explicitly documented permitted audio-tag fields. MusicBrainz offers a more open direct core-data basis but requires more joins, careful licence separation and public-API pacing. Sonovault may reduce that engineering load; it adds a service dependency and restricted app-data lifecycle. CueRithm should retain its PCM-derived analysis and independent taxonomy, and apply returned genre/date/title only under the same protected-value/review policy as every source.
