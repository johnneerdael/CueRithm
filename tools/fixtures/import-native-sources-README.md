# Authored native import fixtures

`import-native-sources.tar.gz` contains small native-format inputs generated by
the independent SDK adapter tests, not vendor libraries or user data. It includes
all 13 source providers. The rekordbox database uses the published test-only key
`generated collection key`. No runtime credentials are captured.

The archive's `manifest.json` records every file's SHA-256 and size. Archive
SHA-256: `2cab295bb7223191456d40ba9167f38bbd707b3dedbdf67ba57c5612002dd99b`.
The matching profile/field capabilities and schema fingerprints are in
`docs/development/fixtures/library-import-native-profiles.json`.

To regenerate native inputs, create a fresh disposable output directory, set
`CUERITHM_IMPORT_FIXTURE_EXPORT` to that directory, and run
`cargo test -p cuerithm-dj-sync --release`. The opt-in fixture helper captures the
first positive authored example for each provider, preserving each selected
artifact's original relative layout. Multi-root examples are skipped by this
portable single-root pack; dedicated adapter tests cover those cases. The
rekordbox test helper uses its runtime-provisioned test reader. Synthetic SQLite
fixtures are copied from coherent captured backups. Test scheduling can choose a
different positive example, so a regenerated archive must receive a new manifest,
hash, capability report and review.

Package the resulting provider directories with sorted paths, zero timestamps
and owner IDs, and gzip timestamp zero. The acceptance test runs actual adapter
capture/read and public library inspect/preview/apply APIs against these inputs;
it compares immutable observations exactly, verifies source artifact hashes,
checks that default imports create no processing, and refuses native writer
promotion. This is D2 fixture evidence. It does not establish D3 sample coverage,
D4 native inbound acceptance, D5 native writes or D6 device behavior.
